# Migration prompts

Use these as request starters. Substitute only confirmed roots, scopes, and
identities; discover native tool schemas before proposing calls.

## Inventory and map

> Inventory `[source root]` read-only for Vault migration into `[target root]`.
> Verify consumer tool readiness and selected canonical root separately from
> migration coverage. Classify every source, read full content, hash it, trace
> links/ownership, and return a dry-run source-to-target map with ordered queue,
> dispositions, conflicts, and coverage totals. Do not write, contact YouTrack KB,
> or alter legacy sources.

## Approved representative batch

> Execute only the approved representative `[linked document cluster]` from
> `[approved map]`. Recheck source hashes, use native Vault writes and full readback,
> resolve forward links second, and maintain the approved ledger. Preserve source
> evidence and authority; stop on conflicts or unsupported preservation. Report tool
> readiness separately from this batch's coverage. Do not begin another batch.

## Resume and completion audit

> Resume `[batch]` using `[ledger]`: verify topology, native tool readiness, and each
> pending source hash before any write. Reconcile every inventory item to one
> disposition, then audit source/target substance, links/backlinks, index/search
> checks, and manifest comparison. Report unresolved blockers and coverage separately;
> do not claim migration complete merely because tools are ready or doctor is green.

## Approved media source

> Preserve `[selected file]` from approved source root `[key]` using the installed
> native file-import contract. Inspect rights/sensitive content and recheck byte
> hash/size first; retain the returned receipt and verify preview or download.
> Create source-supported metadata and a linked analysis article, including
> frame/time references when relevant. Do not base64-encode, extract or execute
> the source, or mark unrelated migration items complete.
