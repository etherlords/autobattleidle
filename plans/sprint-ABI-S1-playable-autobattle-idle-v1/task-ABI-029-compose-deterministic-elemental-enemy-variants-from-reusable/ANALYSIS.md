# ABI-029 analysis

## Complexity and ownership

- **Complexity: XXL.** The task combines content authoring, deterministic domain composition, measured stat modifiers, naming, production Three.js recipes, exhaustive registry coverage, historical-save identity, long-run distribution, and deployed visual QA across at least 96 combinations.
- ABI-037 owns the reusable production-parity concept/test lab. ABI-028 owns ordinary TTK bands. ABI-029 consumes both and owns family-affinity-geometry content plus deterministic identity; it does not build another lab or own boss cadence.
- ABI-036 remains separate because surface-technique research has independent bundle/GPU/licensing decisions. ABI-039 remains separate because cadence/anti-repeat scheduling has independent balance and persistence decisions.

## Verified current state

- ABI-023 and ABI-026 provide reusable enemy builders, named components, semantic pose/head/side anchors, deterministic profiles, animations, and explicit disposal. New variants must extend those owners rather than add one class or mesh factory per combination.
- ABI-020 supplies the accepted stage/economy envelope; ABI-028 will freeze deliberate ordinary TTK composition. Affinity stat modifiers must be simulated against both closed contracts before production porting.
- ABI-037 is the single production-parity lab for reproducible case IDs, all-angle inspection, animation replay, sockets, bounds, and resource counters. Candidate recipes belong there instead of a second task-local renderer.
- Current save identity derives from canonical progression and encounter inputs. Persistence impact remains **no schema change** while family, affinity, and geometry profile reconstruct deterministically after reload.

## Approach

- Audit all current family/profile/modifier/encounter/naming/snapshot/save/visual owners and define compiler-checked registries whose Cartesian composition yields the required matrix without per-combination branches.
- Prototype representative ordinary and boss recipes in ABI-037, obtain explicit design approval, and port only accepted palettes, cues, geometry profiles, sockets, and animations while retaining every legacy body.
- Measure each affinity's small stat modifier in the shared simulator against ABI-020 and ABI-028 envelopes. Domain seed selects family, affinity, geometry, name, visuals, and stats together.
- Verify the exhaustive registry mechanically, but render and inspect a bounded representative matrix serially to avoid unbounded WebGL allocation.

## Risks

- The 96+ combination target can turn into duplicated classes or an unreviewable QA matrix. Registry completeness is automated; human QA uses risk-based representatives and reproducible lab case IDs.
- Visual identity and stat identity can drift if selected in different layers. One canonical composition receipt must feed snapshot and presentation.
- Affinity modifiers can undo ABI-028 TTK variety. The new dependency makes that envelope a precondition rather than a later repair.
- New geometry can detach sockets, break camera framing, or leak resources. Approval and replacement/disposal proof happen in ABI-037 before and after production porting.
