# ABI-016: Space boss encounters and add constrained arena camera orbit

## Goal

Space boss encounters and add constrained arena camera orbit

## Work item

- Type: task
- Priority: high
- Status: Blocked

## Acceptance criteria

- [ ] Boss gaps are always one of 15, 20, 25, or 30 encounters, matching 10 + 5 × N for N in 1..4; a deterministic seeded permutation varies each four-boss cycle so identical progression and reloads produce the same schedule without persisted RNG state.
- [ ] Boss health/reward progression uses the true zero-based boss ordinal from the variable schedule rather than encounter/15, preserving safe-integer saturation and endless rollover behavior.
- [ ] Existing supported saves whose active enemy was generated by the former every-15 schedule load without progress loss; that active encounter finishes unchanged, subsequent spawns use the new schedule, and save/reload remains valid without a schema-version bump.
- [ ] The battlefield camera orbits only around the arena center azimuth: field of view, target, elevation, and radius remain fixed; zoom and pan stay disabled and gameplay state is never changed by camera movement.
- [ ] Desktop pointer drag and narrow/touch drag rotate the view smoothly; ArrowLeft/ArrowRight while the battlefield is focused provide a keyboard equivalent, while Enter/Space and a stationary pointer activation still issue exactly one manual attack.
- [ ] An orbit drag never leaks a manual attack, modal/HUD controls never rotate the camera, resize preserves the orbit angle, and every camera-control listener/resource is removed exactly once on battlefield disposal.
- [ ] Focused unit/integration tests prove schedule gap bounds, deterministic cycle variation, boss ordinals, historical-save compatibility, camera-angle constraints, attack-versus-drag arbitration, resize and disposal; independent browser QA covers desktop and 390px interaction, clean console, bounded listeners/resources, pnpm check, and deployed Pages proof.
